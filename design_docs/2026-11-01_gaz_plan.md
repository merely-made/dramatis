## Open work

### O1. M2: a proof for every key after the first

**Done when:** every key after the first is recorded with the `ProofMethod` that justified it: `Signature` by the previous root for a rotation and by the root for an attested key on `Key` anchors, `DidAuth` (a valid PLC operation) on `Plc` anchors. A key change reported without a proof is stored and marks the contact `Mismatched`, so it surfaces in `alarms()`.

### O2. M2: raise a handle binding by back-claim

**Done when:** a handle binding can be raised by back-claim (the handle's own well-known document names the key or DID) through the same proof vocabulary.

### O3. M2: replay a real PLC history

**Done when:** a test replays `bsky.app`'s four PLC operations, ending in the 2023-11-09 server move, as intake and ends with one contact, two keys, the second carrying `DidAuth`, and no alarm; the same history with the proof withheld ends in `alarms()`.

### O4. M2: WebFinger never becomes an anchor

The first branch landed on 2026-09-30: only the queried Acct handle selects, a unique match preserves its existing key, local or PLC anchor, no match requires a host-selected `LocalId`, and aliases never supply anchors or keys. Fresh key joining and key-rooted resolver intake remain.

**Done when:** a keyless import attaches its endpoints to the contact already holding that `acct:` handle, or else starts a `Local` contact that a key can later join, and keys arrive only from the key-rooted resolver or out of band (a murm invite, an iroh ticket, a QR code); a test proves both paths.

### O5. M2: checking PLC operations (handed to gazette)

Not a gaz phase: gazette owns resolution and can take the crypto. Gazette's README records it as open (`repos/mere/ports/gazette/README.md`: "NIP-05 and checked PLC resolution remain open").

**Done when:** gazette's own plan carries the work and this item is struck here.

### O6. Signalman's stored books

Signalman's desktop loaded and saved a `ContactBook` through Muniment slots before M0.5 changed the stored shape (a list of records instead of a map, the hex map keys gone), so its stored books are in the pre-M0.5 shape. The desktop now pins gaz from this repository (`repos/murm/apps/signalman-desktop/Cargo.toml:63`). Options the S14 pass raised: a one-time migration in murm; declare the books disposable; a legacy decoder in gaz (DOC_POLICY §3 permits shims for real user data).

**Done when:** Mark chooses one, and a test shows a pre-M0.5 book handled as chosen (migrated, refused by name, or decoded).

### O7. M3: mere reconciliation

Conversion glue for `personae` keys and `comms::Identity` endpoints (`repos/mere/crates/shell/comms/src/model.rs`), and the `Contact` rollup the comms model lacks. gaz cannot import `comms`, so the glue lives in mere, which pins this repository by git revision.

**Done when:** mere converts an `Identity`'s endpoints into contact records and `personae` keys into `TypedKey`s with a round-trip test, and the rollup is built or dropped by a ruling.

### O8. M4: recency and merge

Duplicate detection when two records turn out to be one person, which needs a merge rule for conflicting petnames and tiers; it also joins keys that arrived without an attestation to the root that later attests them.

**Done when:** Mark rules the merge rule, and tests show two records merging under it without resolving a mismatch silently (tier architecture invariant 8).
